# MiniMax H3 配置依据与验证边界

本配置在 2026-10-04 首先静态核对官方资料和文件元数据；当时尚未下载权重或执行 H3 渲染。随后完成了下述真实 G4 音视频渲染测试。启动 ComfyUI、网页可访问、GPU 可见，都不能单独证明 H3 能生成视频。

## 配置

- 使用 [Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3) 的 FL2VA 剪枝 INT8 diffusion model、NVFP4 Qwen3-VL encoder、INT8 video VAE 和 FP32 audio VAE，共 40,073,842,159 字节（约 40.07 GB / 37.32 GiB）。不下载 Ref2VA、LoRA 或完整 BF16 模型。
- `models/h3.json` 固定 HF revision 和每个文件的大小、SHA256，依据 [HF 元数据接口](https://huggingface.co/api/models/Comfy-Org/MiniMax-H3?blobs=true)。这些是发布者提供的校验值；下载后仍须完整校验。
- `workflows/h3-api.json` 是按 [官方 T2V 模板](https://github.com/Comfy-Org/workflow_templates/blob/0e5c5efb32ba6f3365d6da07da64aaf668157042/templates/video_minimax_h3_t2v.json) 的节点关系自行构造的 API 工作流，没有复制模板的完整 UI 资产。无需自定义节点或 LoRA。
- 验证输入为 864×480、124 帧、24 fps、20 步、固定 seed 20261004；124 帧符合 `17k+5` 网格，时长约 5.17 秒。这是较低分辨率测试，不代表原生 768p 质量或 2K 输出。固定 seed 也不保证不同 GPU、依赖版本间逐像素相同。

## 依赖与硬件

[ComfyUI 官方指南](https://docs.comfy.org/tutorials/video/minimax/minimax-h3)说明基础 H3 模板要求 ComfyUI 0.30.0 或更新。这里静态核对的是 commit `f1072eb0350638a3390ddb6afbcaa8c6b237c6fd`；部署时还需通过实际 `/object_info` 核实所有节点、输入和模型选项。`SaveVideo` 的 V3 动态组合 API 使用 `format: "mp4"` 和 `format.codec: "h264"` 点号字段，服务端执行前才重建嵌套对象；不能直接提交嵌套的 `format` / `codec` 对象。

[Comfy 模型卡](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/e5eb578a89295337b8ff433a035929ce0279e0b6/README.md)建议可使用 PyTorch cu130 时优先 INT8 ConvRot，并说明 NVFP4 encoder 并不强制要求 Blackwell。实际内核兼容性和显存峰值仍须实测。Google 的 [G4 文档](https://docs.cloud.google.com/compute/docs/gpus)描述 RTX PRO 6000 Blackwell 硬件；Colab 分配情况仍以 `nvidia-smi` 为准。

不建议把 T4 的结果泛化为 G4，或反过来。当前 [ComfyUI H3 类型定义](https://github.com/Comfy-Org/ComfyUI/blob/f1072eb0350638a3390ddb6afbcaa8c6b237c6fd/comfy/supported_models.py)仅支持 BF16/FP32 推理；无 BF16 硬件的 FP16 支持改动 [PR #16508](https://github.com/Comfy-Org/ComfyUI/pull/16508)截至核对时尚未合并。本配置不依赖该分支。

## 模型授权与输出边界

[MiniMax 官方仓库](https://github.com/MiniMax-AI/MiniMax-H3)区分本地 H3-Base 与托管的 H3-Context-IR、H3-Regenerate-2K。本地开放权重提供音视频基础生成；完整官方 2K 流程仍包含托管 API，不能以本配置承诺完全本地 2K。

H3 权重遵循 [MiniMax H3 Community License Agreement](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE)，包含地域、商业和分发条件，**不是无地域限制的开源许可证**。协议把欧盟、英国、韩国和美国列为排除地域。部署和分发仍需遵守模型授权。

[MiniMax 官方硬件 FAQ](https://design.minimax.io/h3)明确表示没有 GPU 时可以使用 Colab GPU runtimes。技术上存在可部署路径。[官方许可证问答](https://huggingface.co/MiniMaxAI/MiniMax-H3/discussions/12?expand=true)讨论排除地域中的使用者申请授权，但没有明确解释“中国使用者通过美国云 GPU 私人测试”究竟按使用者、法律主体还是计算节点所在地判断。本文不对该场景作确定法律判断，也不会仅凭出口 IP 把整个 Colab 方案判定为不可行。官方技术建议不等于一项明确的跨境许可豁免；具体使用仍以适用条款和使用者已有授权为依据。调查的来源和证据层次见 `docs/colab-h3-research.md`。

本项目自己的脚本许可证不能代替 H3 许可证，也不会随 Git 仓库分发模型权重、第三方提示词 skill 或生成媒体。

## 成功标准

实际测试须提交该工作流，观察 `/history` 成功且无节点错误，确认 MP4 可以解码、具有视频及音频轨道，并检查最终资产持久化与重启后取回。HTTP 健康检查只能确认服务启动，不能替代上述验证。

## 2026-10-05 本地实测记录（运行日期为 2026-10-04 UTC）

### Question / Goal

验证固定四文件权重在真实 Colab G4 上完成最小 H3 T2V 音视频生成，以及 ComfyUI `/view` 返回的 MP4 与 Drive 输出一致。此次不评估原生 768p/2K 质量，不比较 `preview` / `final` 参数，也不以该次冷启动测量作通用速度基准。

### Environment

Colab G4 实际分配 NVIDIA RTX PRO 6000 Blackwell Server Edition，`nvidia-smi` 显示总显存 97,887 MiB；Python 3.13.15、PyTorch 2.11.0+cu130。ComfyUI 固定 commit `f1072eb0350638a3390ddb6afbcaa8c6b237c6fd`，模型固定 HF revision `e5eb578a89295337b8ff433a035929ce0279e0b6`。Drive 已经用户授权挂载，服务只监听 `127.0.0.1:8188`，输出指向专用 Drive 目录；无需自定义节点或托管生成 API。

### Steps

1. 启动独立 G4、挂载 Drive，安装固定 ComfyUI commit 并检查服务归属和 HTTP 健康。
2. 下载 manifest 指定的四个文件到 Drive；逐文件验证完整大小和 SHA-256，通过后才提交工作流。
3. 根据官方源码和真实 `/object_info` 修正 `SaveVideo` 的动态字段：先前误把执行函数的嵌套对象当成 API 输入；在本次渲染前改为 `format: "mp4"`、`format.codec: "h264"`。API 输入通过选中分支的严格校验。
4. 提交 864×480、124 帧、24 fps、20 步、seed 20261004 的工作流，查询 history 确认完成无执行错误。
5. 定位真实 Drive MP4，对比 `/view` 与磁盘文件的字节数和 SHA-256；用 PyAV 检查视频、音频元数据并各解码首帧。

### Commands

以下是本轮启动器通过 `subprocess.Popen` 执行的命令，日志留在 VM 的 runtime 目录；模型和媒体只在 Drive。工作流参数默认来自固定的 `workflows/h3-api.json`。

```bash
/content/colab-comfyui-runtime/.venv/bin/python \
  /content/colab-comfyui-launcher/scripts/download_models.py \
  --models-root /content/drive/MyDrive/colab-comfyui-launcher-test/models \
  --max-seconds 720
/content/colab-comfyui-runtime/.venv/bin/python \
  /content/colab-comfyui-launcher/scripts/render_workflow.py \
  --max-seconds 600 \
  --result-file /content/colab-comfyui-runtime/render-result.json
```

### Known Limitations

远端 runner 检验各轨首帧和元数据；随后本地使用 PyAV 19.0.1 完整解码了 124 个视频帧和 162 个音频帧，无解码错误。没有系统评估画面、音质或测量显存峰值；总显存不代表实际最低需求。下载约六分钟，但没有精确开始时间，不能据此计算吞吐或作下载 benchmark。依赖继承 Colab 基础环境，不保证未来镜像与本次一致。

G4 已释放；通过独立 Drive 连接器重新下载此 MP4 后，大小与 SHA256 保持一致，无需继续保留 GPU。随后独立 CPU 的临时公开入口已通过公网 API/WebSocket 和浏览器导入、Run、PNG 预览；这没有验证 H3 的公网浏览器推理。邮箱认证的登录尝试未通过。模型许可条件仍适用；技术成功不增加模型使用权限。

### Architectural Decision

固定 H3 基础权重、原生 ComfyUI API 和 Drive MP4 输出链路已有一次真实运行证据，可继续独立验证生命周期、重取资产与参数选择。它没有实现正式 `RenderWorker` / `StorageBackend` 适配器，不改变主项目 Application / Domain、公开 Render API 或 `preview` / `final` 的含义。模型权重、生成媒体、私有访问地址和凭据不进入 Git。
